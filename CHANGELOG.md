# История изменений

В этом файле документируются все существенные изменения проекта.

Формат основан на [Keep a Changelog](https://keepachangelog.com/), а версии проекта соответствуют [Semantic Versioning](https://semver.org/).

Записи, предшествующие появлению этого файла, восстановлены по истории Git и сведениям о проекте. Исторические разделы `0.1.40` и `0.0.29` объединяют частые патч-релизы в строках версий вместо перечисления каждого микрорелиза. Исторический раздел `0.3.0` также включает изменения промежуточных тегов `0.2.4`–`0.2.9`.

## [0.5.7] - 2026-10-10

### Добавлено

- Добавлен пример восстановления рыночного стрима в приложении: повторная подписка, догрузка закрытых минутных свечей через `GetCandles`, сохранение прогресса после записи, ограниченная задержка между попытками и отмена. Повторными запросами управляет приложение.

### Исправлено

- Команда `account tariff` сохраняет необязательное поле `limitPerSecond` в JSON, включая явный `0`. Таблица разделяет `limit/min`, `limit/sec` и `connections`; остальные поля JSON сохранены.

### Изменено

- В списках доменов и команд CLI-справки минимальный промежуток между названием и описанием увеличен с одного до трёх пробелов; выравнивание колонок сохранено.
- Проверка доли квоты, расчёт разрешённого числа запросов и получение причины отмены перенесены в методы `InMemoryUnaryLimiter`. Диагностика доступа через устаревшие имена сервисов находится в `TInvestNodeSDK`. Публичный API и поведение SDK сохранены.
- Дополнены комментарии к методам классов и уточнена политика комментариев: неочевидное назначение метода нужно пояснять. Рукописный код выровнен по ширине 80 символов с допустимыми исключениями.
- Упрощены примеры и пояснения в README, руководствах и архитектурных заметках; убраны повторы. Описание публичных экспортов собрано в разделе «Экспорты», добавлены ссылки на официальные ресурсы T-Invest. Для SDK используется термин «модуль».
- В политике документации закреплены требования к читаемости примеров и подаче материала. В `CHANGELOG.md` удалены ручные переносы строк.
- В документации лимитной политики уточнён источник квот: актуальный портал разработчиков имеет приоритет над отстающим Markdown-описанием в репозитории контрактов. Добавлен опубликованный ориентир `1000` запросов в минуту с одного IP; значения квот SDK сохранены.

## [0.5.6] - 2026-10-02

### Изменено

- Proto-контракты T-Invest обновлены с 1.49 до 1.51 (`798f880d8010ef4fffe74d0f63d7e5a0d57f23f7`); код TypeScript перегенерирован. Добавлены рейтинги облигаций, валюта цен и статистика рыночных данных, вариационная маржа портфеля и четыре типа счетов. Новые поля доступны в DTO SDK; вариационная маржа также передаётся в `portfolioStream` как в режиме `raw`, так и в поле `payload` JSONL-обёртки. Новые поля сгенерированных DTO имеют значения по умолчанию, заданные proto-контрактами. В приложениях, которые создают полные DTO вручную, нужно обновить объектные литералы или использовать `fromPartial()`.

## [0.5.5] - 2026-10-02

### Изменено

- `icore` обновлён до 2.2.4 с исправлениями разрешения и типизации команд, потокового вывода и рендеринга таблиц и CSV.
- Тип gRPC-клиента выводится из описания сервиса; публичные интерфейсы сервисов SDK сохранены. Внутренняя конфигурация потока описана вариантами по `stream`, а построение запросов для двусторонних и серверных потоков объединено в преобразователе запросов.
- Очередь встроенного ограничителя unary-запросов удаляет отменённые запросы за O(1), сохраняя FIFO, равномерную выдачу разрешений и поведение отмены.
- Общие описания CLI-параметров пагинации по курсору используются основными командами и командами песочницы. Справка проверяется на согласованность со схемами по именам опций, обязательности, допустимым значениям и значениям по умолчанию.
- Все тесты используют строгие проверки. Добавлены проверки границ денежных значений и валидации конфигурации потока. Тесты ограничителя unary-запросов проверяют время выдачи разрешений, FIFO и отмену без привязки к разбиению ожидания на таймеры.
- Пользовательский список CLI-команд и совместимых псевдонимов вынесен в `docs/cli-reference.md`. Заметки о DTO объединены со слоем приложения, а адаптеры — с границами вывода CLI; прежние страницы DTO и адаптеров сохранены как навигация к перенесённым разделам. README, план развития и тестовые политики сокращены за счёт повторов и однотипных примеров. Запреты на добавление и удаление поведения уточнены для изменений вне требований задачи.
- `@bufbuild/protobuf` обновлён до 2.16.0, `@types/node` — до 26.6.4, `oxlint` — до 1.86.0, `oxlint-tsgolint` — до 7.0.2003, `protoc` — до 36.2.0, `ts-proto` — до 2.12.4. После перегенерации 12 proto-модулей изменились только заголовки с версиями инструментов; сгенерированный API остался прежним.

### Исправлено

- CLI-справка показывает поддерживаемый псевдоним `1hour` для свечей и значения по умолчанию фильтров поиска инструментов и пагинации по курсору. Принимаемые опции и поведение команд не изменены.
- `stream run` распознаёт `subscription` в `orders.tradesStream` и фильтрует подтверждения подписки через `includeSubscriptionEvents` до подсчёта `maxEvents`, включая режим `raw`.
- Коды ошибок сертификатов внутри gRPC-ошибки провайдера `UNAVAILABLE` больше не меняют `SdkError.source` на `tls`; распознавание локальных диагностических ошибок TLS сохранено.
- CLI проверяет границы protobuf `int32` для глубины стакана и страниц отчётов. Значения выше `2147483647` отклоняются как ошибки использования CLI до создания SDK; проверки остальных безопасных целых и публичные DTO SDK не изменены.
- `stream run` штатно завершает реальный gRPC-поток по `maxEvents`: итератор закрывается до отмены сигнала сессии, поэтому достижение лимита не превращается в ошибку с кодом завершения `1`. Для ожидающего чтения при таймауте сохранена отмена перед закрытием итератора.
- Пример собственного ограничителя со скользящим окном консервативно обрабатывает дробные квоты. Справочники потокового CLI уточняют вывод статусов подписок, отсутствие поля `action` и общее значение `waitingClose` в одном запросе. Быстрый старт README компилируется с текущими TypeScript-настройками проекта.
- `nice-grpc-common` объявлен прямой зависимостью для выполнения, поскольку публичные сгенерированные декларации импортируют его типы. Проверка типов TypeScript в приложении больше не зависит от поднятия транзитивной зависимости из `nice-grpc` на верхний уровень дерева установки.

### Безопасность

- В файле фиксации зависимостей `@grpc/grpc-js` обновлён до 1.14.5 с исправлениями [GHSA-m9gg-hp2v-232j](https://github.com/grpc/grpc-node/security/advisories/GHSA-m9gg-hp2v-232j) и [GHSA-f596-whhp-79r4](https://github.com/grpc/grpc-node/security/advisories/GHSA-f596-whhp-79r4).

## [0.5.3] - 2026-09-09

### Изменено

- Публичные свойства фасада для доступа к сервисам приведены к именам `marketData` и `stopOrders`.
- Повторяющийся жизненный цикл 66 коротких API-команд вынесен в `runSdkCommand()`. Общее преобразование запросов основной среды и песочницы больше не импортируется через соседние точки входа команд; средства форматирования доступны только из файлов, которым они принадлежат.

- Разрешение unary-квоты больше не перебирает всю таблицу правил для каждого RPC: точный путь метода и общее правило сервиса читаются напрямую с прежним приоритетом.
- Генерация proto переведена с незакреплённого системного `protoc` на локальную зависимость разработки `protoc@36.0.0`. Команда `dev compile-proto` не требует компилятора в `PATH`, не скачивает инструменты во время запуска и воспроизводит прежний сгенерированный API. В заголовках сгенерированных файлов обновлена только версия компилятора.
- Документация переписана более прямым языком без изменения описанных API и контрактов выполнения.
- Полный текст Apache License 2.0 вынесен в корневой `LICENSE-APACHE-2.0`; `LICENSE` по-прежнему содержит только MIT License SDK, а `NOTICE` — границы сторонних компонентов, атрибуцию и условия Protocol Buffers.

## [0.5.1] - 2026-09-08

### Добавлено

- Добавлен отдельный документ о встроенном Russian Trusted Root CA: в нём зафиксированы официальный источник и способ получения, отпечаток X.509, пример использования в официальном T-Invest Python SDK, границы распространения, путь в модуле и пример `tls.rootCertificates`. Лицензия MIT SDK явно не представлена как отдельное лицензионное разрешение на сертификат.
- Добавлен публичный структурный интерфейс `TInvestUnaryLimiter`. Перед каждым unary-вызовом транспорта SDK передаёт реализации полный путь gRPC `path`, выбранные `bucket`, `maxRequests`, `windowMs` и объединённый `AbortSignal`. Жизненным циклом и внешними ресурсами ограничителя управляет приложение.
- Экспортирована необязательная фабрика `createInMemoryUnaryLimiter()` с очередями внутри одного процесса, монотонным временем и отменой ожидающих разрешений на запрос. Один объект можно передать нескольким экземплярам SDK для общего состояния в пределах процесса.
- Добавлено отдельное руководство по собственной реализации ограничителя, отмене, конфликтам квот, распределению ответственности и подключению межпроцессного координатора.

### Изменено

- Модуль подготовлен к публичной публикации в npm под именем `@woodger/t-invest-node-sdk`: снят флаг `private`, для модуля с областью видимости явно задан `publishConfig.access: public`, а сборка архива перенесена с `prepare` на `prepack`. Поддерживаемым каналом установки становится реестр npm; при установке Git-зависимости npm по-прежнему запускает `prepack`. Имя CLI-команды и вывод версии остаются `t-invest-node-sdk`.
- Для proto-контрактов T-Invest версии 1.49 и производного сгенерированного кода зафиксирована Apache License 2.0 со ссылкой на официальный `ru.tinkoff.piapi:java-sdk-grpc-contract:1.49`. Полный текст лицензии приведён в `THIRD_PARTY_NOTICES.md` и включён в архив модуля; лицензия MIT продолжает применяться только к собственному коду SDK.
- Ограничитель unary-запросов больше не создаётся фасадом SDK автоматически. Без `TInvestOptions.unaryLimiter` unary-вызов сразу передаётся транспорту; встроенный CLI также не добавляет ограничитель. Потоки через этот интерфейс не проходят. Ошибки пользовательской реализации не маскируются под ошибки gRPC.
- `UnaryLimits` теперь хранит явные пары `{ maxRequests, windowMs }` вместо нормализованных чисел запросов в минуту. Секундная квота `PostOrder` передаётся как `15` запросов за `1_000` мс без изменения допустимого всплеска запросов.

### Удалено

- Удалена опция `trackLimits`. Для прежнего локального поведения нужно явно передать `unaryLimiter: createInMemoryUnaryLimiter()`; отсутствие ограничителя соответствует прежнему `trackLimits: false`.

## [0.5.0] - 2026-09-07

### Исправлено

- Денежные значения и котировки в CLI-отчётах теперь формируются из `units` и `nano` без арифметики с плавающей точкой. Малые дроби сохраняют десятичную форму, а наносы не теряются при больших целых частях.
- Положительные целочисленные CLI-опции ограничены безопасным диапазоном JavaScript. Торговые `quantity`, глубина стакана и параметры выполнения потока больше не округляются при разборе значений вне этого диапазона.
- CLI принимает даты только в формате RFC 3339 с явным `Z` или числовым смещением и отклоняет несуществующие календарные даты. Проверки справки команд, имён доменов и интервалов потока больше не принимают свойства прототипа объекта как допустимые значения.
- Ограничение частоты unary-запросов и таймауты потоков используют монотонное время. Ожидания длиннее диапазона таймера Node.js разбиваются на безопасные части.
- Локальная ошибка разбора входящего gRPC-ответа сохраняет код `Internal`, но получает `source: 'sdk'`; ошибка провайдера `INTERNAL` остаётся `source: 'grpc'`.
- Неизвестные имена сервисов и пути методов gRPC в `unaryLimits` отклоняются как `InvalidArgument` с `source: 'sdk'`. Вложенный контракт `UnaryLimitsDefinition` типизирован именами поддерживаемых unary-сервисов и их методов.

### Изменено

- `@bufbuild/protobuf` обновлён до 2.14.1, `@types/node` — до 26.4.1, `oxlint` — до 1.81.0, `ts-proto` — до 2.12.2.
- CLI-команды больше не содержат отдельный слой повторного разбора исходных опций: проверка по схеме выполняется один раз механизмами команд `icore`, а функции построения запросов получают уже типизированные значения. Удалены 83 вспомогательные функции разбора, используемые только в тестах, и дублирующие тесты; поведение команд при выполнении не изменилось.
- Из внутренних модулей удалены неиспользуемый `stdoutInterceptor` и несколько фасадов для тестов над реестром команд и функциями построения потоковых запросов. Тесты проверяют непосредственно объекты, используемые рабочим кодом.
- В Oxlint включены `typescript/no-deprecated` и `typescript/no-unsafe-assignment`. Небезопасные присваивания результата `JSON.parse` в тестах средств отчётности заменены побайтовыми проверками JSON-вывода, а написанный вручную код больше не обращается к устаревшему API.
- Локальные proto-файлы сверены с актуальным официальным выпуском T-Invest `invest-contracts` 1.49 и перегенерированы с `ts-proto` 2.12.2. Публичные DTO и контракты сервисов не изменились; сгенерированные декодеры теперь отклоняют protobuf-вложения глубже 100 уровней.
- Документация сверена с текущим публичным API, CLI, составом модуля и поведением при выполнении: исправлены примеры конфигурации потока и коды завершения, добавлено требование Node.js `>=20.19.0`, обновлены архитектурные карты и навигация, а источник вспомогательных proto Google зафиксирован в `contracts/upstream.json`.
- Лицензия MIT собственного кода SDK отделена от уведомлений о сторонних компонентах. Для производных от `google/api/field_behavior.proto` добавлены атрибуция и полный текст Apache License 2.0, включаемые в архив модуля.

### Удалено

- Из нормализованных JSON-отчётов CLI для облигаций, валют, ETF, фьючерсов, опционов и акций удалены устаревшие `klong` и `kshort`. Поля `dlong` и `dshort` сохраняют собственную семантику и не используются как замена. Публичные сгенерированные DTO и прямые вызовы сервисов не изменены.

## [0.4.4] - 2026-08-13

### Исправлено

## [0.1.40] - 2026-06-28

Этот раздел объединяет изменения версий модуля с `0.1.0` по `0.1.40`.

### Добавлено

- В `bootstrap` добавлен широкий набор команд CLI с каноническими именами `<service> <method>`.
- Добавлены команды CLI для пользователей, рыночных данных, инструментов, операций, заявок, стоп-заявок, песочницы и потоковых сценариев.
- Добавлены команды CLI с подтверждением изменений заявок, стоп-заявок, избранного и песочницы.
- Добавлена настройка потокового CLI для серверных потоков и начальных запросов `marketdata.marketDataStream`.
- Добавлены справочник потокового CLI и документация его конфигурации.
- Добавлены контракты отчётов приложения и переиспользуемое форматирование значений отчётов.
- В инфраструктурный слой добавлены средства вывода JSON, CSV и таблиц.
- Добавлены средства записи в stdout/stderr с обработкой обратного давления.
- Добавлена документация по чистой архитектуре, командам, границам вывода, тестированию, именованию, скриптам, зависимостям и политике изменений.
- Добавлено локальное сокращение `yarn cli`.

### Изменено

- Механизмы CLI в `bootstrap` переведены на реестр команд и схемы опций `icore`.
- Прежние `CliArgs`, `ArgGuards` и обёртки совместимости заменены декларативным разбором `icore`.
- Запуск тестов перенесён из локальных файлов наборов тестов в `fwa`.
- Исполняемые точки входа `bootstrap` собраны в `src/bootstrap/bin`.
- Исполняемая точка входа CLI перенесена с сохранением поведения команды модуля.
- Инфраструктура gRPC перенесена в `src/infrastructure/transport/grpc`.
- Форматирование вывода CLI разделено между отчётами приложения, средствами отображения инфраструктурного слоя и средствами записи вывода.
- Идентификаторы инструментов CLI приведены к опции `--instrument-id`.
- Денежные значения в JSON-выводе CLI переведены из объединённых строк в структурированные поля `amount` и `currency`.
- Форматирование скалярных значений отчётов для денежных сумм, котировок и дат собрано в одном месте.
- Генерация proto обновлена для рекурсивной обработки исходных proto-файлов.
- Код из proto перегенерирован с `protoc` 3.21.
- После эксперимента с `grpc-tools` генерация proto возвращена к системному `protoc`.
- Запуск скомпилированных тестов объединён через `fwa`.
- Сокращена документация быстрого старта CLI.

### Исправлено

- Исправлена обработка обратного давления stdout и stderr при выводе CLI.
- Исправлена обработка статусов и ошибок потокового вывода, а также длительной записи вывода.

### Удалено

- Удалены лишние сценарии GitHub Actions для документации.
- Прежние псевдонимы CLI удалены перед публикацией нового набора команд.
