# Ошибки и lifecycle

> Type: Guide. Здесь показано, как распознавать `SdkError`, определять причину ошибки по стабильным полям и решать, можно ли повторить запрос.

## Сужение типа по коду и источнику

Один `code` не всегда определяет причину ошибки. Например, `CANCELLED` может прийти от локального `AbortSignal` или от провайдера. Когда это влияет на решение приложения, проверяйте сочетание `code` и `source`.

Во фрагментах ниже `sdk` — уже созданный экземпляр SDK. Его настройка и освобождение показаны в руководстве [Первый SDK-вызов](./getting-started.md). Каждый пример рассматривает отдельный случай; остальные ошибки передаются вызывающему коду.

```ts
import { isSdkError, SdkErrorCode } from '@woodger/t-invest-node-sdk';
```

### Ошибка TLS

```ts
try {
  await sdk.users.getAccounts({});
}
catch (error) {
  if (
    isSdkError(error, SdkErrorCode.Unavailable)
    && error.source === 'tls'
  ) {
    console.error('Проверьте адрес API и настройки CA-сертификата');
  }
  else {
    throw error;
  }
}
```

### Локальный deadline

```ts
const deadline = AbortSignal.timeout(5_000);

try {
  await sdk.users.getAccounts({}, { signal: deadline });
}
catch (error) {
  if (
    deadline.aborted
    && isSdkError(error, SdkErrorCode.Cancelled)
    && error.source === 'abort'
  ) {
    console.error('Истёк срок ожидания запроса');
  }
  else {
    throw error;
  }
}
```

### Ошибка авторизации

```ts
try {
  await sdk.users.getAccounts({});
}
catch (error) {
  if (
    isSdkError(error, SdkErrorCode.Unauthenticated)
    && error.source === 'grpc'
  ) {
    console.error('Провайдер отклонил токен', { path: error.path });
  }
  else {
    throw error;
  }
}
```

### Лимит сообщения и квота провайдера

Один `ResourceExhausted` может обозначать разные ограничения. Здесь ошибка после диагностики передаётся дальше: решение о повторе вызова остаётся у приложения.

```ts
try {
  await sdk.users.getAccounts({});
}
catch (error) {
  if (!isSdkError(error, SdkErrorCode.ResourceExhausted)) {
    throw error;
  }

  if (error.source === 'sdk') {
    console.error('Ответ превысил локальный лимит gRPC-сообщения', {
      path: error.path
    });
  }
  else if (error.source === 'grpc') {
    console.error('Исчерпана квота провайдера', {
      path: error.path,
      details: error.details
    });
  }

  throw error;
}
```

## Коды ошибок

SDK преобразует статусы gRPC в одноимённые стабильные `SdkErrorCode`.

Для ошибки с `source: 'grpc'` поле `code` содержит символьное имя стандартного статуса gRPC, отличного от `OK`. Например:

```ts
SdkErrorCode.InvalidArgument;    // 'INVALID_ARGUMENT'
SdkErrorCode.NotFound;           // 'NOT_FOUND'
SdkErrorCode.Unauthenticated;    // 'UNAUTHENTICATED'
SdkErrorCode.ResourceExhausted;  // 'RESOURCE_EXHAUSTED'
```

В набор кодов ошибок не входит `OK`; полный список задаёт экспортируемый enum `SdkErrorCode`. `SdkErrorCode.SdkClosed` и `SdkErrorCode.UnknownUnaryLimit` относятся к SDK, а не к gRPC. Поле `code` само по себе не указывает источник ошибки, поэтому при необходимости проверяйте его вместе с `source`.

## Интерпретация источника

| `source` | Значение |
| --- | --- |
| `grpc` | Ошибка получена от транспорта или провайдера |
| `tls` | Не пройдена проверка цепочки сертификатов или имени сервера |
| `abort` | Приложение отменило вызов через `AbortSignal` |
| `lifecycle` | SDK уже закрыт |
| `sdk` | SDK отклонил локальную конфигурацию, запрос или состояние выполнения |

`SdkErrorCode.InvalidArgument` получает `source: 'grpc'`, если проверка не пройдена на стороне провайдера, и `source: 'sdk'` при локальной ошибке конфигурации. Поэтому определяйте источник не только по `code`.

Не каждая ошибка во время выполнения — это `SdkError`. Сначала вызовите `isSdkError()`, а неизвестную ошибку сохраните или передайте дальше без принудительного приведения типа. Например, SDK не оборачивает в `SdkError` синхронное исключение обработчика `onHeader` или `onTrailer`, переданного приложением.

SDK помечает однозначные ошибки проверки цепочки сертификатов и имени сервера как `SdkErrorCode.Unavailable` с `source: 'tls'`. Обычный `UNAVAILABLE` от провайдера или сети, включая ошибки DNS, отказ или сброс соединения и таймаут, сохраняет `source: 'grpc'`. По `source` приложение может распознать ошибку TLS и завершить вызов, пропустив обычные повторные попытки при недоступности сервиса. Поля `path`, `details` и `cause` остаются доступными для диагностики.

Если входящее gRPC-сообщение превышает внутренний лимит SDK, ошибка получает `SdkErrorCode.ResourceExhausted` и `source: 'sdk'`. Исчерпанная квота провайдера возвращает тот же код с `source: 'grpc'`. В обоих случаях SDK сохраняет исходные `path`, `details` и `cause`; различайте причины по `source`, а не по диагностическому тексту.

Локальные ошибки сериализации запроса и разбора ответа получают `SdkErrorCode.Internal` с `source: 'sdk'`, а `INTERNAL` от провайдера сохраняет `source: 'grpc'`. SDK оставляет `path`, `details` и `cause` для диагностики; для классификации достаточно `source`.

## Диагностические поля

- `path` содержит путь gRPC-метода, когда он известен.
- `details` содержит диагностический текст транспорта или провайдера. Это не стабильный код бизнес-ошибки провайдера, поэтому не разбирайте его регулярным выражением.
- `cause` сохраняет исходную ошибку для диагностики. Бизнес-логика не должна зависеть от класса ошибки `nice-grpc`.

`isSdkError()` распознаёт совместимый `SdkError` из другой физической копии модуля в том же JavaScript realm. После передачи через JSON, IPC или сериализации в worker нужен отдельный протокол приложения.

## Закрытие SDK

`sdk.close()` можно вызывать повторно. Первый вызов:

- запрещает получение новых клиентов сервисов и вызовы через ранее полученные клиенты;
- отменяет операции, которые еще ждут локальную unary-квоту;
- закрывает общий канал.

`sdk.close()` не ждёт операции, уже переданные транспорту. Чтобы завершить работу, отмените их через собственный `AbortSignal`, дождитесь завершения и только затем закройте SDK. Порядок завершения потоков подробно разобран в руководстве [Потоки и отмена](./streams-and-cancellation.md).

## Граница повторных попыток

Один статус gRPC не определяет, можно ли повторить запрос. Перед повтором проверьте:

- идемпотентна ли операция;
- мог ли провайдер уже выполнить изменение;
- есть ли метаданные повтора или ограничения частоты запросов;
- какая задержка между попытками и общее ограничение времени допустимы для приложения.

Особенно это относится к `ResourceExhausted`, `Unavailable`, `DeadlineExceeded` и RPC, изменяющим данные. Универсальный перехватчик повторных запросов на уровне SDK скрыл бы эти различия.

Для `ResourceExhausted` сначала проверяйте `source`. Значение `sdk` означает, что входящее сообщение превысило внутренний транспортный лимит SDK; повтор того же вызова ничего не изменит. Значение `grpc` указывает на ответ провайдера, но тоже не даёт достаточных оснований для повтора без учёта метаданных, идемпотентности и задержки между попытками.
