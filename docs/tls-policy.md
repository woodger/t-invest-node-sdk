# TLS-доверие

> Type: Reference. Здесь описано, как SDK проверяет TLS-соединение и как передать собственные корневые сертификаты.

## Настройки по умолчанию для T-Invest

Для подключения к T-Invest API в рабочей среде и песочнице нужны сертификаты НУЦ Минцифры РФ. SDK поставляет Russian Trusted Root CA в формате PEM и при `useSsl: true` передаёт его в `ChannelCredentials.createSsl()`.

Сертификат действует только для gRPC-канала конкретного экземпляра SDK:

- системное хранилище доверенных сертификатов не изменяется;
- `NODE_EXTRA_CA_CERTS` не используется;
- сертификаты не скачиваются при установке и работе SDK;
- TLS продолжает проверять имя сервера;
- сервер T-Invest передаёт промежуточный Russian Trusted Sub CA в своей цепочке.

Официальные адреса подключения и требования к сертификатам описаны в [документации T-Invest](https://developer.tbank.ru/invest/intro/developer/network).

## Происхождение встроенного сертификата

Источник сертификата, его получение, отпечаток X.509, сведения о распространении, путь в модуле и пример замены описаны в документе [«Встроенный Russian Trusted Root CA»](./bundled-ca.md).

## Переопределение для экземпляра SDK

Для подключения к собственному или тестовому серверу передайте корневые сертификаты в формате PEM через `tls.rootCertificates`. SDK принимает их содержимое в `Buffer`, а не путь к файлу. Переданные сертификаты полностью заменяют встроенный сертификат для нового канала; при `useSsl: false` SDK игнорирует настройки TLS. Пример приведён в [документе о встроенном сертификате](./bundled-ca.md#переопределение-в-коде-приложения).

## Граница безопасности

Встроенный корневой сертификат позволяет проверять TLS-цепочку T-Invest. Он не закрепляет конкретный публичный ключ T-Bank: владелец доверенного центра сертификации может выпустить сертификат для другого сервера. Если потребуется привязка к конкретному ключу (SPKI pinning), нужно отдельно определить правила проверки и замены ключей.

Порядок проверяемого обновления сертификата описан в [документе о встроенном сертификате](./bundled-ca.md#обновление-сертификата).

## Ошибки проверки сертификата

Если TLS однозначно сообщает об ошибке проверки цепочки сертификатов или несовпадении имени сервера, SDK возвращает `SdkErrorCode.Unavailable` с `source: 'tls'`. Ошибка сохраняет путь gRPC-метода в `path`, исходные `details` и `cause` для диагностики.

Обычные ошибки `UNAVAILABLE` от провайдера или сети, включая ошибки DNS, отказ или сброс соединения и таймаут, сохраняют `source: 'grpc'`. Решение о повторном запросе принимает приложение; SDK не считает эти ошибки достаточным основанием для повтора.

Низкоуровневый код ошибки TLS не входит в публичный контракт SDK. Для классификации проверяйте `code` и `source`; `details` и `cause` служат только для диагностики.
