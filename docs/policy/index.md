# Политики проекта

> Type: Policy. Этот документ задает навигацию по policy-разделу и фиксирует общий смысл ограничений на изменение проекта.

Раздел с правилами изменения проекта, архитектурными ограничениями и нефункциональными требованиями.

Цель документации раздела:

- предсказуемость поведения SDK;
- воспроизводимость сборки;
- устойчивость публичного API;
- отсутствие случайных изменений;
- контролируемое развитие кода.

Проект относится к production backend SDK: он зависит от wire-контрактов T-Invest API, generated-кода и compiled `dist` artifacts.

Поэтому в проекте действуют строгие правила изменения кода, тестов, scripts, зависимостей и документации.

Политики обязательны для разработчиков, ревьюеров и агентов, вносящих изменения в репозиторий.

## С чего начать

- [Правило принятия решений](./decision-rule.md) - базовый фильтр: нужно ли вообще делать изменение.
- [Политика внесения изменений](./change-policy.md) - правило минимального допустимого изменения.
- [Архитектурная политика](./architecture.md) - ограничения на направление зависимостей и границы слоев.
- [Политика жизненности кода](./code-liveness-policy.md) - правила audit и deletion pass для dead/orphaned code.

## Когда читать этот раздел

- перед началом изменений в коде;
- при code review;
- когда есть сомнение, допустима ли правка;
- когда изменение касается scripts, документации, зависимостей или архитектуры;
- когда меняется test runner, generated code или proto workflow.
