# Правило принятия решений

> Type: Policy. Этот документ задает базовый фильтр перед любым изменением кода.

Если изменение не требуется — не делать.

Если изменение добавляет поведение — не делать.

Если изменение удаляет поведение — не делать.

Если изменение делает "как обычно" — не делать.

Если изменение кажется безопасным — не делать.

Если изменение кажется правильным — не делать.

Если есть сомнение — оставить как есть.

Существующий код считается намеренным.

## Практика применения

Перед изменением полезно последовательно проверить:

1. Требуется ли это задачей напрямую.
2. Меняет ли это поведение, pipeline или структуру проекта.
3. Можно ли решить задачу меньшим изменением.
4. Не основано ли решение на эвристике вместо требования.

## Примеры

Правильное решение:

- исправить конкретную условную ветку, если задача про неверный расчет
- добавить тест на уже требуемое поведение

Неправильное решение:

- переписать модуль "раз уж трогаем"
- добавить очистку артефактов, потому что так привычнее
- менять dependency graph ради субъективного ощущения порядка
