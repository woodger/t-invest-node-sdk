# Политика внесения изменений

> Type: Policy. Здесь описана минимально допустимая область изменения.

## Минимальность изменений

Изменение должно быть минимально необходимым для решения задачи.

Запрещено:

- крупный рефакторинг без запроса
- cleanup без обоснования
- изменение стиля вне затронутой области
- изменение архитектуры
- изменение pipeline
- изменение scripts
- изменение поведения

Существующий код считается намеренным.

Если изменение не требуется — его нельзя делать.

## Локальные улучшения

Небольшие улучшения допустимы, если они напрямую связаны с задачей.

Допустимо:

- устранить локальное дублирование
- улучшить нейминг
- упростить читаемость
- исправить соседний очевидный дефект
- улучшить локальные тесты

Условия:

- поведение не меняется
- изменение остается локальным
- улучшение помогает решению текущей задачи

Если улучшение выходит за рамки задачи, предложите его отдельно.

## Примеры

Допустимо:

- исправить конкретный дефект в одном модуле без сопутствующего переписывания соседнего кода
- добавить точечный тест для нового требования без изменения существующего test pipeline
- расширить уже используемую ветку `if`, если это прямо требуется задачей

Недопустимо:

- массово переименовывать сущности ради единообразия
- выполнять несвязанные переименования в других модулях
- переписать модуль целиком вместо исправления одной ветки
- менять структуру файлов только потому, что так кажется удобнее

## Границы модулей

Не сохраняйте плохую структуру только потому, что она уже существует.

Допустимо:

- исправлять локально неудачный нейминг
- уточнять ответственность модуля
- переносить небольшой объем кода для улучшения читаемости

Недопустимо:

- перепроектирование подсистемы
- массовое перемещение файлов
- изменение архитектурных границ без запроса

## Хорошие практики

- перед изменением сформулировать, какое именно требование задачи покрывается правкой
- ограничивать diff только теми файлами, которые реально участвуют в задаче
- проверять, не меняет ли правка поведение вне требуемого сценария

## Проблемы окружения

Не меняйте код проекта из-за проблем окружения.

Если проверка не запускается из-за отсутствующих инструментов, прав, cache, shell utilities или ограничений контейнера, остановитесь, опишите проблему и запросите решение.

Допустимо использовать локальный временный cache/workdir только если это не меняет проект и не расширяет задачу.
