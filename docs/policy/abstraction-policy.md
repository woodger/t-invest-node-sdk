# Политика выделения абстракций

> Type: Policy. Этот документ задает правила вынесения повторяющегося кода в переиспользуемые модули.

Повторяющийся код следует выносить в переиспользуемые модули, если это действительно улучшает поддержку.

Разрешено выносить код, если:

- логика повторяется
- код используется в нескольких местах
- код сложный
- код относится к инфраструктуре
- код должен тестироваться отдельно

Запрещено:

- выносить код ради красоты
- делать helpers ради helpers
- создавать utils без ответственности
- создавать абстракции на будущее

Правило:

- 1 раз — оставить inline
- 2 раза — подумать
- много раз — вынести

## Примеры

Допустимо:

- вынести повторяющийся парсинг конфигурации, если он используется в нескольких модулях
- создать отдельный adapter для повторяемой filesystem-логики
- выделить общий модуль, если он имеет четкую ответственность и отдельные тесты

Недопустимо:

- создать `utils.ts` ради одной функции, используемой в одном месте
- оборачивать стандартный вызов в helper без новой ответственности
- выносить две похожие строки в абстракцию, если это скрывает важное различие поведения

## Хорошие практики

- сначала проверить, действительно ли логика повторяется, а не только внешне похожа
- при вынесении явно определить ответственность нового модуля
- для повторно используемого кода сразу добавлять тесты на выделенное поведение
